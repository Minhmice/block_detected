<threat_model>
Assets: track identity, last-good geometry freshness, truthful confidence, and bounded debug memory/render cost.
Trust boundaries: YOLO can reuse/misassign IDs, boxes can jump, CV can return weak/conflicting candidates, and verbose debug content can grow with line density.
Threats and mitigations:
- HIGH stale geometry attached to a different object: require same track key plus IoU >= 0.5, reject large center/size jumps, and reject strong point conflict before hold.
- HIGH stale result persisting indefinitely: compute hold age once per frame, cap at 3, and derive held score from the immutable last-good score with `0.8 ** age`.
- MEDIUM confidence laundering: mark held results explicitly and preserve the failed attempt reason in typed debug metadata rather than reporting them as freshly detected.
- MEDIUM debug CPU/memory amplification: basic is the default; verbose stores only configured top-N candidates and candidate generation remains bounded.
Residual risk: an upstream tracker may retain an incorrect ID with a slowly moving bbox that passes IoU guards; cross-object re-identification is outside this phase.
</threat_model>
