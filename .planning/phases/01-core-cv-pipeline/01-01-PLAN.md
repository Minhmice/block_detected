<threat_model>
Assets: frame integrity, track/result association, bounded Pi 5 CPU/memory use, and truthful geometry output.
Trust boundaries: NumPy frames and YOLO detections are caller-provided and may contain empty arrays, invalid bbox order, out-of-frame coordinates, non-finite floats, or adversarial line density.
Threats and mitigations:
- HIGH CPU exhaustion from combinatorial line candidates: keep separate front/right candidate caps in `HexDetectorConfig`, stop generation at those caps, and test bounded output.
- HIGH false geometry from missing right-face evidence: rectangle is a first-class four-point result; C,D remain `None` unless a validated right face exists.
- MEDIUM malformed input causing OpenCV errors: validate frame shape/size and finite bbox coordinates, clamp before slicing, and return `ROI_EMPTY` rather than raising from CV calls.
- MEDIUM ambiguous rejection telemetry: map all exits to the stable RejectReason enum and test serialization values.
Residual risk: image content can still produce a high-scoring false positive; dataset calibration remains a later verification concern.
</threat_model>
